# Учебные месяцы программ (`apps.academic_progress`)

Вместо «24 / 72» руководитель видит учебный месяц группы:
**2-й месяц · 3 / 12 занятий**, предмет месяца, сколько осталось, и отдельно —
общий прогресс курса.

## Настройки (Настройки учебной программы)

| Где | Модель |
|---|---|
| Занятий в учебном месяце (12 / 20 / своё), продолжительность, основной и дополнительные предметы, какие занятия заполняют месяц | `ProgramCurriculum` — одна на программу (`academy.Course`) |
| Предмет и план отдельного месяца (порядок месяцев = порядок изучения) | `CurriculumMonth` — только отличия от значений по умолчанию |
| Сколько занятий группа провела до LMS (подтверждение истории) | `GroupProgressAdjustment` |

Доступ: администратор и операционный директор — все программы; Team Lead —
программы своих направлений (`TeamLeadDirection`; без направлений — все);
директор, тренер, ассистент — просмотр.

## Расчёт (только на сервере, ничего не хранится)

* Учитываются **проведённые** занятия группы (`Lesson.status = completed`).
  Запланированные и отменённые — нет.
* Каждое занятие считается один раз: по (программа, номер занятия) и по
  (предмет, дата, время). Перенесённое занятие — отменённый оригинал и
  замена с тем же номером — даёт +1 только после проведения замены; повторная
  запись того же занятия не добавляет.
* «Только основные предметы» — занятия дополнительных предметов (English,
  Soft…) месяц не двигают; «Все предметы» — двигают.
* Учебный месяц: занятия заполняют месяцы по порядку; ровно заполненный
  месяц — начинается следующий (0 / N); все заполнены — «Курс пройден».
  Календарный месяц не используется.
* Пропуски студентов прогресс группы не уменьшают. Прогресс студента
  (посещённые им занятия текущего месяца и курса) показывается отдельно.
* Изменение настроек пересчитывает месяц по тем же проведённым занятиям —
  занятия, посещаемость и история не меняются.

**«Требуется настройка»** — данные не придумываются:
* для программы не настроены учебные месяцы;
* занятия группы в LMS начинаются не с №1 (первые не внесены) и история не
  подтверждена — укажите «Проведено занятий до LMS» (0 — тоже ответ).

Прежний общий прогресс по плану занятий (`plan`) остаётся в API и в
подсказке колонки «Общий прогресс курса».

## API — `/api/v1/academic-progress/`

| Метод | Путь | Что |
|---|---|---|
| GET | `meta/` | предметы, право изменять |
| GET | `programs/` | программы с настройками и числом групп «Требуется настройка» |
| GET/PUT | `programs/{course_id}/` | настройки программы (`lessons_per_month`, `duration_months`, `main_subject`, `extra_subjects`, `count_mode`, `months[]`) |
| GET | `groups/{id}/` | текущий месяц, предмет, прогресс блока и курса, месяцы, прогресс студентов |
| PUT | `groups/{id}/history/` | `{lessons_before_lms}` — подтвердить историю группы |

В кабинете операционного директора (`/api/v1/operations/academy/groups/`,
`…/groups/{id}/`) у каждой группы — поле `academic` с тем же расчётом.

## Интерфейс

* Операционный директор: Академия → «Группы» (колонки «Учебный месяц» и
  «Общий прогресс курса»), страница группы (карточка «Учебный месяц» и раздел
  «Учебные месяцы»), «Настройки программ» (`/operations/academy/programs`).
* Team Lead: «Настройки программ» (`/team-lead/programs`).
