# Посещаемость и ДЗ — месячная матрица (`apps.attendance_matrix`)

Единая таблица «студенты × занятия» для всех ролей академии: тренер отмечает,
ассистент помогает, Team Lead контролирует направление, операционный директор
видит всю академию.

## Данные

Новых «отметок» не создаётся — используются существующие записи академии:

| Что | Где хранится |
|---|---|
| Посещаемость (присутствовал / опоздал / уваж. причина / без причины) | `academy.Attendance.status` |
| Причина отсутствия (обязательна для «уважительной») | `academy.Attendance.excuse_reason` (новое поле) |
| Комментарий тренера | `academy.Attendance.comment` |
| Кто последним изменил отметку | `academy.Attendance.updated_by` (новое поле) |
| Домашнее задание | `academy.HomeworkResult` каждого `Homework` занятия |

Посещаемость и ДЗ — две отдельные записи, ни одна не перезаписывает другую.
Миграции только добавляют поля и таблицы: существующие данные не меняются.

Новые таблицы приложения:

* `GroupAssistant` — ассистент, назначенный в группу; `can_edit` — может ли
  отмечать (иначе только просмотр и комментарии).
* `TeamLeadDirection` — направления (предметы) Team Lead. Без направлений
  Team Lead видит всю академию, как раньше.
* `MatrixSettings` (одна запись) — пороги предупреждений и права Team Lead /
  операционного директора на изменение отметок.
* `AttendanceChangeLog` — журнал изменений: кто, когда, поле «было → стало».

Всё это настраивается в Django admin.

## Статусы ячейки

| Код | Цвет | Значение |
|---|---|---|
| `done` | зелёный | присутствовал (или опоздал) и сдал ДЗ / ДЗ не задано |
| `partial` | светло-зелёный | присутствовал, ДЗ не сдано |
| `excused` | жёлтый | уважительная причина |
| `absent` | красный | без причины |
| `empty` | серый | занятие прошло, отметки нет |
| `planned` | пунктир | занятие ещё впереди |
| `no_lesson` | бледный | студент ещё не пришёл в группу / уже ушёл |

Колонки — только реальные занятия группы за период; отменённые занятия,
выходные и дни без занятий в таблицу и статистику не попадают.

ДЗ: «сдано» — все задания занятия SUBMITTED / CHECKED / LATE; «не сдано» —
NOT_SUBMITTED или срок прошёл без результата (без срока — занятие проведено);
«ещё не срок» — не учитывается.

Процент посещаемости — присутствовал / отмечено (уважительная причина входит
в «отмечено»), как во всей аналитике академии.

## Предупреждения (настраиваются)

| Правило | По умолчанию | Уровень |
|---|---|---|
| Пропусков подряд | 2 | предупреждение |
| Пропусков за период | 3 | внимание |
| Пропусков за период | 4+ | критично |
| Несданных ДЗ | 3+ | предупреждение |

## Доступ (проверяется на сервере — `access.py`)

| Роль | Видит | Изменяет |
|---|---|---|
| Администратор | все группы | всё |
| Тренер | свои группы, только свои занятия | свои занятия |
| Ассистент | только назначенные группы | если `GroupAssistant.can_edit`, иначе только комментарии |
| Team Lead | группы своих направлений | только если `MatrixSettings.team_lead_can_edit` |
| Операционный директор | всю академию | только если `MatrixSettings.operations_director_can_edit` |

Чужая группа — 404, запрещённое действие — 403. Отменённое занятие не
редактируется; будущее занятие нельзя отметить заранее; удалить отметку
завершённого занятия может только администратор.

## API — `/api/v1/attendance-matrix/`

| Метод | Путь | Что |
|---|---|---|
| GET | `meta/` | группы, направления, тренеры для фильтров |
| GET | `groups/{id}/?period=day\|week\|month&date=YYYY-MM-DD` | матрица группы; фильтры `search`, `status`, `homework`, `level`, `subject` (id или `none`; кнопки предметов — `subjects` в ответе), `teacher` |
| GET | `groups/{id}/export/` | то же в Excel (цвета сохранены) |
| GET | `cell/?lesson=&student=` | ячейка: студент, группа, дата, статусы, причина, комментарий, кто/когда изменил, история |
| PUT | `cell/` | `{lesson, student, attendance?, excuse_reason?, comment?, homework?: done\|missed}` |
| GET | `overview/?date=&subject=&teacher=&group=` | сводка за месяц: группы, тренеры, проблемные студенты, рейтинг, динамика за 6 месяцев, уважительные причины (`excused`, без причины помечены), работа ассистентов (`assistants`), журнал изменений (`history`) |
| GET | `overview/export/` | сводка в Excel |
| GET/PATCH | `settings/` | пороги (админ, опер. директор); права на изменение (только админ) |

## Интерфейс

* Тренер / Team Lead / админ: группа → вкладка «Посещаемость» → «Таблица за
  период» (старый «Журнал отметок» сохранён рядом).
* Ассистент: группа → «Посещаемость»; раздел «Посещаемость и ДЗ».
* Team Lead / админ: «Посещаемость и ДЗ» (`/app/attendance-monitoring`).
* Операционный директор: Академия → «Посещаемость и ДЗ»
  (`/operations/academy/attendance`).

## Совместимость со старыми данными

Таблица показывает всю существующую посещаемость, ничего не переписывая:

* **Статусы в другом написании** (`PRESENT`, ` Late `, `attended`, «был»…)
  читаются как канонические при каждом чтении; в базе значение не меняется.
  Нераспознанное значение показывается как «нет данных» и выводится аудитом.
* **Отметки на отменённых занятиях** видны (колонка зачёркнута), но в
  статистику не входят и не редактируются.
* **Тренер** видит группы, где он когда-либо вёл занятия, даже если его
  расписание или программа уже неактивны.
* **Ассистент без назначения** видит все группы только для чтения (как в
  рабочем месте ассистента); после назначения — только свои группы.
* **Период «Всё время»** — вся история группы от первого до последнего занятия.
* «Журнал отметок» во вкладке группы листается по страницам (раньше
  показывались только первые 20 записей).

Проверка на любой базе (только чтение):

```
python manage.py audit_attendance_matrix [--group ID]
```

Выводит написания статусов, отметки на отменённых занятиях, отметки
студентов из других групп, доступ ролей и по каждой группе «в базе N, в
таблице N». Итог «Не попало в таблицу: 0» значит, что видна каждая запись.
