# Массовое копирование данных (apps.bulk_copy)

Администратор копирует учебные записи из одной группы / предмета / периода в
другие вместо ручного заполнения. LMS → «Массовое копирование»
(`/app/bulk-copy`). Журнал операций — также в Django admin (только чтение).

## Что копируется

Только существующие модели академии — ничего не дублируется:

| Данные | Модель | Поля |
|---|---|---|
| Посещаемость | `academy.Attendance` | статус (присутствовал / опоздал / не был / уважительная), причина для «уважительной», комментарий — по флагу «Копировать комментарии» |
| Домашние задания | `academy.HomeworkResult` | статус, `submitted_at`, `checked_at`, комментарий тренера — по флагу |
| Оценки | `HomeworkResult.score` (0–10) | балл; результат, созданный ради оценки, получает и статус источника |

Не копируются: сами задания (контент тренера), попытки экзаменов
(`apps.testing` — автоматически проверенные ответы), оценки тренера за период
(для них — «Стипендии → Копировать оценки между предметами»), личные и
учётные данные студентов.

## Правила

* **Студенты — только по `Student.id`**, никогда по имени, номеру строки или
  позиции. Студент должен сейчас состоять в группе целевого занятия (правило
  `Attendance.clean`), поэтому при копировании между группами сопоставляются
  только те, кто сейчас в целевой группе; остальные показаны как
  «не сопоставлены».
* **Занятия сопоставляются явно**: пары «занятие-источник → целевое занятие».
  Сервер предлагает пары по порядку (n-е проведённое занятие → n-е), но
  администратор проверяет и меняет каждую. Неверные пары (занятие вне
  выбранных группы / предмета / периода, будущее занятие, повтор, нет прав)
  показываются и пропускаются. ДЗ пары сопоставляются по порядку создания и
  только при одинаковом числе заданий; иначе результаты ДЗ этой пары не
  копируются (показано в предпросмотре).
* Отменённые занятия не участвуют; в будущие занятия ничего не пишется.
* Отсутствие записи в источнике ничего не создаёт и не удаляет.
  «Пропускать пустые значения» сохраняет значение цели там, где поле
  источника пустое (нет оценки, пустой комментарий).
* Существующие записи цели сохраняются или перезаписываются — перезапись
  требует отдельного подтверждения (галочка и `confirm_overwrite`, иначе 428).
  Совпадающие значения не переписываются — повтор той же операции ничего не меняет.
* Режимы: всё / только посещаемость / только ДЗ / только оценки; все или
  выбранные студенты (выбранные записи = выбранные студенты × выбранные пары занятий).

## Выполнение, аудит, отмена

* Предпросмотр ничего не пишет. Применение пересчитывает план в одной
  транзакции с блокировкой целевых записей и сверяет отпечаток предпросмотра
  (`fingerprint`): если данные изменились — 409 и ничего не записано. Любая
  ошибка откатывает всю операцию; неудачная попытка остаётся в журнале со
  статусом «Ошибка — ничего не изменено».
* `operation_id` (UUID клиента) — повторный запрос не выполняет операцию дважды.
* Больше 1500 записей при настроенном брокере Celery — фоновая задача
  `bulk_copy.run`; журнал обновляется сам. Без брокера — сразу.
* Каждая изменённая запись — в `BulkCopyItem` (было / стало). Операция —
  в `BulkCopyOperation`: администратор, группы и предметы, периоды, категории,
  создано / перезаписано / пропущено (с причинами), время, идентификатор.
* Каждое изменение посещаемости также пишется в историю журнала посещаемости
  (`AttendanceChangeLog`), как ручная правка.
* **Отмена** (один раз): созданные записи удаляются, перезаписанные
  восстанавливаются — только если запись всё ещё равна скопированной.
  Изменённые после копирования записи не трогаются («Отменено частично»).

## Побочные эффекты

Сохранение посещаемости, как и при ручной отметке, пересчитывает списания
уроков в биллинге (`apps.billing.signals` → `sync_lesson`). Предпросмотр
предупреждает, сколько занятий это затронет. Отмена удаляет созданные отметки
и сама запускает пересчёт этих занятий (у биллинга нет сигнала на удаление
отметки).

## Права

* Администратор (роль ADMIN или superuser) — всё.
* Сотрудник с правом `bulk_copy.run_bulk_copy` («Может выполнять массовое
  копирование данных») — только в пределах своих прав в журнале посещаемости:
  группа-источник должна быть ему видна, каждое целевое занятие — доступно
  ему для полной правки (тренер — только свои занятия). Видит только свои операции.
* Тренеры без права, аккаунты кабинета ученика — 403.

## API (`/api/v1/bulk-copy/operations/`)

| Метод | Путь | |
|---|---|---|
| GET | `options/` · `options/?group=<id>` | группы; предметы группы |
| POST | `preview/` | предпросмотр |
| POST | `/` | применить (`fingerprint`, `operation_id`, `confirm_overwrite`) — 201, или 202 если в очереди |
| GET | `/` · `<id>/` | журнал · операция с записями |
| POST | `<id>/undo/` | отмена |

Параметры: `source_group`, `source_subject`, `source_start`, `source_end`,
`target_group`, `target_subject`, `target_start`, `target_end`,
`categories` (`attendance` / `homework` / `scores`), `lesson_map`
(`[{source, target}]` или `null` — предложить), `mode` (`all` / `selected`),
`student_ids`, `conflict` (`preserve` / `overwrite`), `skip_empty`,
`copy_comments`. Ошибки: 400, 403, 409 (данные изменились / уже отменено),
428 (нужно подтвердить перезапись).

## Развёртывание

```
python manage.py migrate bulk_copy
```
Сотрудникам, кроме администраторов, право выдаётся в Django admin.
