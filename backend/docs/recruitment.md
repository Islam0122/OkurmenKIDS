# Подбор персонала: карьерный сайт и HR-кабинет

Приложение `apps.recruitment`, фронтенд — `features/careers` (публичный сайт)
и `features/hr` (HR-кабинет, роль `hr_manager`).

## Путь кандидата

1. HR создаёт вакансию (`/hr/vacancies/new`) — она сохраняется **черновиком**.
2. HR нажимает «Опубликовать» — вакансия появляется на `/careers`.
3. Посетитель открывает `/careers/vacancies/<slug>` и отправляет отклик без регистрации.
4. Отклик (этап «Новый отклик») появляется в `/hr/candidates` (таблица и доска этапов).
5. HR просматривает анкету и резюме, назначает собеседование, фиксирует оценку и результат.
6. На этапе «Предложение о работе» — «Принять на работу»: учётная запись LMS
   создаётся после подтверждения (роли РОП, менеджер по продажам, маркетинг)
   или уходит запросом администратору (остальные непривилегированные роли:
   Django admin → «Запросы на учётные записи» → «Одобрить»).

## Модели

| Модель | Назначение |
|---|---|
| `Vacancy` | Карточка вакансии и статус: черновик → опубликована ⇄ пауза → закрыта → архив |
| `Candidate` | Человек: ФИО, контакты (нормализуются для поиска совпадений), профиль |
| `Application` | Отклик: вакансия, этап (11 этапов), источник, анкета, резюме, согласие, номер заявки |
| `InternalNote` | Внутренние заметки HR |
| `Interview` | Собеседование: статусы «запланировано / проведено / перенесено / отменено / не пришёл», оценки |
| `AccountRequest` | Запрос учётной записи для роли вне полномочий HR |
| `HRActivity` | Журнал: переходы этапов, собеседования, доступ к резюме, найм |

Миграции: `0002_careers_schema` → `0003_careers_data` (каждый прежний
кандидат становится человеком + откликом, «Открыта» → «Черновик», заметки →
`InternalNote`) → `0004_careers_cleanup`.

## API

Публичный (`/api/v1/public/careers/`, без входа, лимит по IP):
`GET filters/`, `GET vacancies/`, `GET vacancies/<slug>/` (404 / 410 для закрытой),
`POST vacancies/<slug>/apply/` (multipart; `submission_token` защищает от повторной отправки).

HR (`/api/v1/hr/`, только `hr_manager`): `vacancies/` (+`status/`), `candidates/`
(+`notes/`, `history/`, `merge/`, `erase/`), `applications/` (+`status/`,
`resume/`, `board/`, `hire/`, `account-request/`, `not-duplicate/`),
`interviews/` (+`cancel/`, `no-show/`, `result/`), `account-requests/`,
`reminders/`, `dashboard/`, `reports/daily/`, `reports/monthly/` (`?export=csv`).

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `RECRUITMENT_PRIVATE_ROOT` | `MEDIA_ROOT/private` | Закрытое хранилище резюме (не отдаётся через `/media/`) |
| `RECRUITMENT_RESUME_MAX_MB` | `5` | Максимальный размер резюме |
| `RECRUITMENT_CONSENT_VERSION` | `2026-10` | Версия текста согласия (текст — `features/careers/content.ts`) |
| `RECRUITMENT_RETENTION_DAYS` | `365` | Срок хранения данных кандидатов без найма |
| `CAREERS_READ_RATE` / `CAREERS_APPLY_RATE` | `1200/hour` / `10/hour` | Лимиты публичного API |

Отдельное развёртывание сайта: сборка фронтенда с `VITE_APP_MODE=careers`
(«/» открывает `/careers`). В основной сборке сайт доступен по `/careers`.

Удаление данных по сроку хранения: `python manage.py purge_candidate_data`
(показать) и `--apply` (удалить) — например, раз в сутки по расписанию.
