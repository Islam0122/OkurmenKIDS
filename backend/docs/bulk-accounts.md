# Пакетное создание кабинетов учеников

Assistant Workspace → **Студенты → Кабинеты** (`/assistant/students/accounts`).
API: `/api/v1/assistant/bulk-accounts/…`. Доступ — администратор и активный ассистент.

## Что делает

* Берёт **активных** студентов (все или выбранные группы; одна группа — частный случай).
* Студенты с уже существующим кабинетом (`portal.StudentLink`) отмечаются как «аккаунт уже был» и **не трогаются**: ни новый пользователь, ни сброс пароля.
* Для остальных создаёт кабинет через `apps.portal.services.accounts.provision_account` — тот же код, что у одиночного создания: роль `STUDENT_PARENT`, пароль из `secrets`, хэш в `User.password`, `must_change_password=True` (первый вход — только смена пароля), связь со студентом, запись в журнал действий.
* Логин: `begaly01`, `begaly02`… — транслитерированное имя и первый свободный двузначный номер (номер и есть суффикс дубликата).
* Каждый студент — отдельная транзакция: ошибка одного не останавливает пакет; причина ошибки показывается в результате.
* «Повторить неудачные» создаёт **новый пакет** только из тех студентов пакета, у которых всё ещё нет кабинета.

## Пароли и выгрузка

* В базе **нет открытых паролей**. Пока файл не выгружен, временный пароль хранится зашифрованным (Fernet, ключ выводится через HKDF из `SECRET_KEY`) в `BulkAccountRunItem.sealed_password`.
* Excel (`Student ID, Student Full Name, Group, Username, Temporary Password, Account Status, Creation Date`) скачивается **один раз**: после скачивания все пароли пакета удаляются.
* Если файл не скачан за 24 часа — пароли удаляются по истечении срока (`export_state = expired`). Такие студенты получают новый пароль через карточку студента («Сбросить пароль»).
* Скачать может только тот, кто запустил пакет, и администратор. Ответ `no-store`, `attachment`, `nosniff`.
* Журнал (`LogEntry`) фиксирует, кто и когда запустил пакет, создал аккаунты и выгрузил файл — пароли в журнал не попадают.

**Важно для эксплуатации:** шифрованные пароли лежат в БД до выгрузки или истечения срока. Поэтому:
* не меняйте `SECRET_KEY` между созданием и выгрузкой (иначе пароли не расшифровываются — файл покажет «не удалось прочитать», сбросьте пароли);
* резервные копии БД содержат эти шифротексты до 24 часов — обращайтесь с ними как с секретами;
* файл Excel не зашифрован паролем (openpyxl этого не умеет) — храните и пересылайте его как секрет.

## Ограничения

* Одновременно выполняется только один пакет; незавершённый пакет нужно продолжить («Продолжить пакет»), а не запускать новый.
* Пакет обрабатывается шагами по 10 студентов (`POST …/process/`), поэтому долгое хеширование паролей не упирается в таймаут запроса.
* Студенты одной семьи получают отдельные кабинеты; объединение с существующим семейным аккаунтом делается вручную (карточка студента → «Привязать к аккаунту»).

## Тесты

`python manage.py test apps.portal.test_bulk_accounts` — формат логинов, CSPRNG-пароли и их хранение, пропуск существующих аккаунтов, связь со студентом и роль, области выбора, ошибки и повтор без дублей, одноразовый XLSX, истечение срока, права доступа, смена пароля при первом входе.
