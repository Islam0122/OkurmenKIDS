# Учёт прихода и ухода сотрудников (QR-код офиса)

Приложение `apps.staff_attendance` (API `/api/v1/staff-attendance/`) и раздел
фронтенда `/attendance/*`, `/admin/attendance/*`. Не путать с
`academy.Attendance` — это посещаемость **студентов** на занятиях.

Сотрудник — существующий `users.User`, категория — `User.role`. Отдельной
таблицы сотрудников нет; новых ролей модуль не вводит.

## Страницы

| Маршрут | Кто | Что |
|---|---|---|
| `/attendance` | любой отслеживаемый сотрудник | переход на страницу своей категории |
| `/attendance/teacher` | Тренер | личный кабинет отметки |
| `/attendance/accounting` | Бухгалтер | личный кабинет отметки (без финансовых данных) |
| `/attendance/assistant` | Ассистент | личный кабинет отметки |
| `/attendance/office` | Администратор, Директор, Team Lead | личный кабинет отметки |
| `/attendance/scan?office=<код>` | любой отслеживаемый сотрудник | сюда ведёт QR, отсканированный обычной камерой телефона |
| `/attendance/management` | у кого есть доступ к отчётам | отчёты для руководства / HR |
| `/admin/attendance` | у кого есть доступ к отчётам | главная панель: карточки, таблица, карточка сотрудника, исправления, CSV |
| `/admin/attendance/locations` | управление | офисы, QR-коды (просмотр, печать, копирование URL), координаты, радиус, вкл/выкл |
| `/admin/attendance/settings` | управление | расписание, льгота, GPS, роли, офисная сеть, личные расписания |

Личный кабинет: имя и фото (фото есть только у профиля тренера), часы
офиса, статус дня (ещё не пришёл / на работе / день завершён), крупная
кнопка «📷 Сканировать QR», приход, уход, время на работе, опоздание,
месячная статистика и история.

Ссылки добавлены в существующие меню: LMS (`navItems`, сайдбар Team Lead),
Assistant Workspace, Бухгалтерия.

## Права

Решает backend (`apps/staff_attendance/access.py`); фронтенд только прячет
недоступное.

| Действие | Кто |
|---|---|
| Отметка и своя история | активный пользователь, чья роль включена в настройке «Кто отмечает» (по умолчанию все роли) |
| Отчёты | Администратор, Директор — все; Team Lead — только тренеры; любой с правом `staff_attendance.view_attendance_reports` |
| Исправления | Администратор или право `staff_attendance.adjust_attendance` |
| Офисы, QR, настройки, личные расписания | Администратор или право `staff_attendance.manage_attendance` |

Права-исключения (например, для HR) выдаются через Django permissions без
новой роли. Бухгалтер изолирован `AccountingIsolationMiddleware`: ему открыт
только префикс `/api/v1/staff-attendance/me/`, админ-эндпоинты — 403.

## Логика отметки

1. Кнопка открывает камеру (только после нажатия, только HTTPS). QR
   распознаётся `BarcodeDetector`, где он есть, иначе `jsQR`.
2. Ссылка проверяется: HTTPS, путь `/attendance/scan`, код офиса.
3. `GET me/locations/<код>/` — офис существует и активен.
4. Геолокация запрашивается **заново** перед каждой отметкой
   (`maximumAge: 0`, высокая точность), в фоне не отслеживается.
5. `POST me/check-in/` или `me/check-out/` с кодом, координатами,
   точностью и `idempotency_key`. Id сотрудника и время устройства не
   принимаются.
6. Сервер: роль, офис, офисная сеть (если включена), точность ≤ допустимой,
   расстояние по Haversine ≤ радиуса (+1 см на погрешность вычислений),
   состояние сессии. Успех показывается только после ответа сервера.

Правила: нет открытой сессии → приход; есть → уход; повторный приход и
уход без прихода → 409. Несколько сессий в день допустимы (вышел и
вернулся); опоздание считается только по первой сессии дня. Открытая
сессия прошлого дня закрывается как «Нет ухода» (время ухода не
выдумывается) при следующем приходе, командой
`close_stale_attendance_sessions` или задачей Celery
`staff_attendance.close_stale_sessions` (раз в час в `CELERY_BEAT_SCHEDULE`).

Гонки: все отметки сотрудника идут под `SELECT … FOR UPDATE` строки
пользователя; частичный уникальный индекс `staff_att_one_open_session_per_user`
не даёт создать вторую открытую сессию; `(user, idempotency_key)` уникален —
повтор запроса возвращает первый результат (200, `replayed: true`).

Время хранится в UTC (серверное), показывается в часовом поясе офиса из
настроек (по умолчанию `Asia/Bishkek`), рабочий день (`work_date`) — дата
по поясу офиса.

## Опоздания и расписание

Ожидаемое начало дня: личное расписание сотрудника → (если включено) первое
занятие тренера в LMS минус «прийти заранее» → общее расписание. Опоздание —
минуты от начала дня, если приход позже начала + льготное время.

«Нет прихода» ставится только после окончания рабочего окна сотрудника в
рабочий для него день. До даты «Учёт ведётся с» и до регистрации сотрудника в
LMS дни помечаются «Учёт не вёлся» и не считаются пропусками.

Модуль **не** подключён к зарплате: продолжительность — время между приходом
и уходом, а не оплачиваемые часы.

## Модели и миграции

* `0001_initial` — `AttendanceSettings` (одна запись), `AttendanceLocation`,
  `AttendanceWorkSchedule`, `AttendanceSession`, `AttendanceEvent`,
  `AttendanceAdjustment`, `AttendanceAdminLog`; индексы, CHECK-ограничения,
  частичные уникальные индексы, права `view_attendance_reports`,
  `adjust_attendance`, `manage_attendance`.
* `0002_main_office` — главный офис (42.88543338574097, 74.60303549712579,
  радиус 100 м), если офисов ещё нет, и запись настроек. Отметок не создаёт.

Миграции только добавляют таблицы — существующие данные не меняются.
Координаты сотрудника не хранятся: только расстояние до центра и точность.

## API

Личные (`me/`): `status/`, `locations/<код>/`, `check-in/`, `check-out/`,
`history/?date_from&date_to&page`, `stats/?month=YYYY-MM`.

Админ (`admin/`): `meta/`, `overview/?date…`, `records/?date|date_from+date_to,
search, role, status, location, ordering, page, page_size`, `export/` (CSV по
тем же фильтрам), `employees/<id>/?date_from&date_to`,
`employees/<id>/schedule/` (PUT/DELETE), `sessions/` (POST — ручная запись),
`sessions/<id>/adjust/` (POST), `adjustments/`, `locations/` (GET/POST),
`locations/<id>/` (GET/PATCH), `locations/<id>/qr.svg`, `settings/`
(GET/PATCH), `schedules/`, `log/`.

Ошибки отметки: `{"detail": "...", "code": "..."}` — `geolocation_required`,
`accuracy_required`, `low_accuracy`, `out_of_range`, `location_not_found`,
`location_inactive`, `network_mismatch`, `already_checked_in`,
`not_checked_in`, `stale_session`, `idempotency_conflict`.

CSV: `;`-разделитель, UTF-8 с BOM; ячейки, начинающиеся с `= + - @` и
табуляции, экранируются апострофом.

## Настройки окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ATTENDANCE_QR_BASE_URL` | `LMS_FRONTEND_URL` | начало ссылки в QR (должен быть HTTPS-адрес LMS) |
| `ATTENDANCE_TRUST_X_FORWARDED_FOR` | `False` | брать IP клиента из `X-Forwarded-For` (только за доверенным прокси) — для проверки офисной сети |
| `STAFF_ATTENDANCE_MARK_RATE` | `30/hour` | лимит отметок на пользователя |

## Ограничения

* Геолокацию браузера можно подменить, постоянный QR — сфотографировать.
  Сервер проверяет вход, офис, точность и радиус, но абсолютной защиты это не
  даёт. Дополнительно можно включить проверку офисной сети (нужен статический
  внешний IP офиса и правильный IP клиента за прокси).
* Камера и геолокация работают только по HTTPS.
* `BarcodeDetector` есть не во всех браузерах — там работает `jsQR`
  (подгружается отдельным чанком).
* Строки отчёта считаются в Python по всем отслеживаемым сотрудникам — это
  рассчитано на штат академии (десятки–сотни человек), период — не длиннее 93
  дней.
* Фото в карточке есть только у тренеров (`Teacher.image`); у остальных —
  инициалы.

## Развёртывание

1. `pip install -r requirements.txt` (добавлен `segno` для QR в SVG),
   `npm ci` во `frontend/` (добавлен `jsqr`).
2. `python manage.py migrate`.
3. Проверить `LMS_FRONTEND_URL` / `ATTENDANCE_QR_BASE_URL` — это адрес в QR.
4. В `/admin/attendance/settings` проверить расписание, льготу, «Учёт
   ведётся с», роли; при необходимости — личные расписания.
5. В `/admin/attendance/locations` сверить координаты офиса на карте,
   распечатать QR и повесить у входа.
6. Если Celery Beat не запущен, добавить в cron
   `python manage.py close_stale_attendance_sessions` (иначе сессии
   закрываются при следующем приходе сотрудника).
