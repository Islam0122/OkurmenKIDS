# Кабинет ученика и родителя (Student & Parent Portal)

Одна роль на семью — `User.Role.STUDENT_PARENT` (`student_parent`). Отдельных
ролей «ученик» и «родитель» нет: аккаунт связан с одним или несколькими
студентами и видит только их.

| Где | Что |
|---|---|
| `apps/portal/` | модели аккаунтов, изоляция, API кабинета, отчёты, PDF |
| `apps/assistant/` | создание студента вместе с аккаунтом, управление аккаунтом |
| `frontend/src/features/studentPortal/` | кабинет `/student` (ru / ky) |
| `frontend/src/features/assistant/actions/StudentAccount.tsx` | данные для входа, панель аккаунта |

## Данные

* **`portal.PortalAccount`** — портальная сторона `User`: `must_change_password`,
  `can_view_payments`, когда выданы данные для входа, телефон родителя (цифры —
  для поиска кабинета семьи). Пароль хранится только в `User.password`
  (хешер Django).
* **`portal.StudentLink`** — какие студенты привязаны к аккаунту (уникально по
  паре). Всё, что видит аккаунт, начинается с этих связей
  (`services/scope.py`): чужой id → 404.
* **`academy.Student`** — новые необязательные поля `parent_name`, `birth_date`,
  `photo`, `branch`. Филиал — существующая таблица `website.Branch` (та же, что
  на публичном сайте), не копия.
* **`academy.HomeworkResult`** — `submission_text`, `submission_link`: что ученик
  сдал из кабинета. Тренер проверяет ту же строку (статус / балл / комментарий),
  как и раньше; для тренера поля только для чтения.

Миграции: `users.0008`, `academy.0028`, `portal.0001` — только добавление
полей/таблиц, без переноса данных.

## Создание аккаунта (ассистент)

`POST /api/v1/assistant/students/` — обязательные в интерфейсе: имя, фамилия,
телефон родителя, филиал (если филиалы заведены), группа. В одной транзакции:

1. `enroll_student` (как и раньше) создаёт студента;
2. либо `create_account=true` (по умолчанию) — новый аккаунт:
   логин `имя.фамилия` латиницей (кыргызские ң/ө/ү транслитерируются), при
   совпадении — с цифрой (`aibek.asanov2`); можно задать свой (`login`);
3. либо `link_account=<id>` — добавить в кабинет брата/сестры (интерфейс сам
   предлагает кабинет семьи по тому же телефону родителя —
   `GET students/account-check/`).

Временный пароль: 12 символов из CSPRNG (`secrets`) без похожих символов,
формат `Hk7m-pQ3x-9tRw` (~68 бит), проходит `AUTH_PASSWORD_VALIDATORS`.
Он есть **только** в ответе на создание / сброс (`credentials`), с
`Cache-Control: no-store`. Нигде не сохраняется, не логируется, не
экспортируется и больше не отдаётся. В интерфейсе — «Копировать логин»,
«Копировать пароль», «Копировать всё».

У аккаунта нет настоящего e-mail; `User.email` уникален и обязателен, поэтому
ставится адрес в зарезервированном домене `*.portal.okurmenkids.invalid`
(никогда не доставляется), а в API `/auth/me/` он отдаётся пустым.

### Управление (Admin или Assistant, `IsAdminOrAssistant`)

| Эндпоинт `/api/v1/assistant/students/{id}/…` | |
|---|---|
| `account/` GET / POST | статус аккаунта / создать аккаунт существующему студенту |
| `account/reset-password/` POST | новый временный пароль, снова обязательная смена |
| `account/login/` PATCH | сменить логин (формат + уникальность, без учёта регистра) |
| `account/active/` POST `{value}` | включить / отключить вход |
| `account/payments/` POST `{value}` | показывать ли семье оплату |
| `account/link/`, `account/unlink/` | привязать к кабинету семьи / отвязать (последнего ребёнка отвязать нельзя — отключите вход) |
| `photo/` POST / DELETE | фото студента |
| `students/export/?export_format=xlsx\|csv` | список с текущими фильтрами, с логином и статусом кабинета, без паролей |

Фильтры списка: `branch`, `account=none|pending|active|disabled`; поиск — и по логину.

**Аудит.** Каждое действие пишет `LogEntry` (кто, когда, что) на студента — оно
видно в «Истории» студента — и на пользователя. Пароль в журнал не попадает.

## Вход и изоляция

* Вход — обычный `/api/v1/auth/login/` (JWT). `UserSerializer` отдаёт
  `must_change_password`.
* `apps.portal.access.PortalIsolationMiddleware`: аккаунту `student_parent`
  открыты только вход, `/api/v1/portal/` и анонимные `/api/v1/public/…`.
  Любой другой API и `/admin/` — 403 `portal_only`, независимо от
  `permission_classes` конкретного представления (новый эндпоинт LMS тоже
  закрыт автоматически). Пока временный пароль не сменён, внутри кабинета
  открыты только `me/` и `password/` — 403 `password_change_required`.
* Аккаунты кабинета — не сотрудники: `User.objects.staff()` и
  `User.staff_role_choices()` исключают их, и они применены во всех списках
  сотрудников (операционный кабинет, KPI, задачи, учёт прихода/ухода,
  бухгалтерия, HR, Django admin «Добавить пользователя»).

## API кабинета — `/api/v1/portal/`

`me/`, `password/`, и для каждого `students/{id}/`: `dashboard/`, `schedule/?start&end`
(≤ 62 дней), `homework/?state=open|done|pending|overdue|submitted|late|checked`
(с пагинацией), `homework/{id}/`, `homework/{id}/submit/`, `attendance/?year&month`,
`notifications/`, `feedback/`, `payments/` (403, если оплата скрыта),
`reports/monthly/?year&month`, `reports/monthly/pdf/?year&month&lang=ru|ky`.

## Откуда цифры (ничего не считается заново)

* **Занятия ученика** — по той же истории членства, что и KPI
  (`analytics.student_progress.membership`): занятие группы до зачисления или
  после ухода ученику не показывается; занятие с его отметкой — всегда.
* **Месячный отчёт** — `student_progress_detail` (проведённые занятия,
  посещаемость по отмеченным, ДЗ только там, где оно было, «нет данных» вместо
  0 %) по каждой группе ученика за месяц, суммировано. Сравнение — с прошлым
  месяцем, динамика — за 6 месяцев.
* **XP** — правила публичного рейтинга (`leaderboard.student_xp`, добавлен
  необязательный фильтр `student_ids`). Уровни — только представление XP
  (100, 300, 600, 1000 …).
* **Достижения** — только из реальных записей: утверждённые стипендии, месяц без
  пропусков (≥ 4 отметок), задания на 10 баллов, количество сданных заданий, уровень.
* **Отзывы** — комментарии тренеров к ДЗ и к отметкам, оценки `TrainerFeedback`.
* **Уведомления** — выводятся из данных на лету (просрочено / скоро срок /
  новое / проверено задание, отменённое занятие, ожидается оплата), не хранятся;
  backend отдаёт код и параметры, текст — на языке интерфейса.
* **Оплата** — `billing.services.archive.student_finance`, открытые начисления и
  подтверждённые платежи.

## Интерфейс

`/student`: боковое меню на десктопе, нижняя навигация на телефоне,
переключатель детей (если их несколько), RU / KG (выбор хранится на
устройстве; PDF запрашивается на том же языке). Графики — inline SVG, пара
цветов проверена валидатором палитры (зелёный `#2f8f5b`, синий `#2563a8`),
у динамики есть табличный вид.
