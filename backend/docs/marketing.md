# Кабинет маркетинга

Рабочее место сотрудника с ролью `marketing`: `/marketing` во фронтенде,
`/api/v1/marketing/` в API (приложение `apps.marketing`).

## Доступ

* API — только активный сотрудник маркетинга или администратор
  (`apps.users.permissions.IsMarketingTeam`); остальным ролям — 403.
* Роль остаётся «с базовым доступом» (`User.STAFF_ONLY_ROLES`):
  `AccountingIsolationMiddleware` пропускает её только к входу, учёту
  прихода и ухода и к `/api/v1/marketing/`. Зарплаты, сотрудники HR, студенты
  и остальная LMS закрыты (403 `staff_only`).
* О людях API отдаёт только имя ответственного — без контактов и других
  персональных данных. Ответственным можно назначить только активного
  сотрудника маркетинга.
* Править контент-план и задачи может любой сотрудник маркетинга; удалить
  запись — её автор или администратор.

## Данные

| Модель | Поля |
|---|---|
| `ContentItem` | тема, канал, формат, дата и время выхода, ответственный, статус (идея → подготовка → согласование → запланировано → опубликовано), заметки, ссылка на пост; `published_at` ставит сервер |
| `MarketingTask` | название, описание, срок, приоритет, статус (к выполнению / в работе / выполнено), ответственный; `completed_at` ставит сервер, «просрочено» вычисляется |

## API

| Метод и путь | Что делает |
|---|---|
| `GET meta/` | каналы, форматы, статусы, приоритеты, команда (имена), сегодня |
| `GET dashboard/?date_from&date_to` | сводка задач и плана, ближайшие задачи и публикации (по умолчанию — текущий месяц) |
| `GET reports/?period=week\|month&date=` | выполнено задач (в срок / с опозданием), подготовлено и опубликовано, выполнение плана, динамика, по каналам и сотрудникам |
| `content/` | CRUD; фильтры `status` (через запятую), `channel`, `responsible`, `mine=1`, `date_from`/`date_to` (≤ 62 дня), `no_date=1`, `search` |
| `tasks/` | CRUD; фильтры `status` (+ `open`, `overdue`), `priority`, `responsible`, `mine=1`, `due=today\|week\|overdue\|none`, `search` |

«Выполнение плана» — доля опубликованных среди публикаций плана, чья дата
прошла (сегодняшние — только уже вышедшие).

Рекламные кампании (`Campaign`, `campaigns/`, страница `/marketing/campaigns`):
канал, ответственный, даты, бюджет, расход, лиды, продажи, результат. CRM в
системе нет, поэтому лиды и продажи кампании вносит маркетинг; CPL и конверсия
вычисляются. Бюджет, расход и CPL API отдаёт только маркетингу, администратору,
директору и (если разрешено в настройках операционного модуля) операционному
директору — см. docs/operations.md.

## Приход и уход

Отдельной посещаемости у кабинета нет. Кнопка в шапке открывает тот же
`MarkFlow` (QR-код офиса → свежая геолокация → проверки сервера), что и
страница `/attendance/staff`; статус рабочего дня — `GET
/api/v1/staff-attendance/me/status/`. История — `/attendance/staff`.

## Моя зарплата

Пятый раздел кабинета (`/marketing/my-salary`, короткий адрес `/my-salary`) —
та же страница и тот же API, что у тренеров, ассистентов и HR:
`/api/v1/accounting/my/…` (`EmployeeSalaryProfile → Payroll → PayrollPayment`).
Своего расчёта у маркетинга нет. Сотрудник всегда берётся из сессии —
`employee`, `user` и другие id в запросе игнорируются. Middleware изоляции
открывает маркетингу и HR только префикс `/api/v1/accounting/my/`
(`apps.accounting.access.own_salary_roles`); остальная бухгалтерия — 403.
Пока бухгалтерия не завела профиль и не рассчитала зарплату, раздел
показывает пустое состояние без сумм.
