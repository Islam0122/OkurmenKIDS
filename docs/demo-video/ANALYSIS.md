# Анализ проекта Okurmen Kids LMS

## Состав репозитория

| Часть | Технологии | Назначение |
|---|---|---|
| `backend/` | Python, Django 6, DRF, SimpleJWT, drf-spectacular, PostgreSQL, Celery + Redis, ReportLab, openpyxl, pywebpush, Playwright | REST API `/api/v1/`, бизнес-логика, фоновые задачи, PDF/Excel-отчёты, web-push |
| `frontend/` | React 19, TypeScript, Vite, TanStack Query, React Hook Form + Zod, Tailwind 4, framer-motion, jsQR | LMS: кабинеты всех ролей, учёт посещаемости, бухгалтерия, финансы; PWA (service worker, push) |
| `training-portal/` | React + TypeScript | Тренинг-портал (тесты, экзамены) |
| `okurmen-public-website/` | React + TypeScript | Публичный сайт академии (CMS — из LMS) |

Масштаб: **26** Django-приложений, **154** модели, **228** URL-маршрутов
в `urls.py`, **3 468** backend-тестов (`def test_`), **440** TSX-компонентов
и **83** тестовых файла во frontend, **12** ролей пользователей.

Деплой: backend — `Dockerfile` + Railway (`deployment/railway-cron.json`
запускает `run_scheduled_tasks` каждые 30 минут); три фронтенда — Vercel
(`vercel.json`).

## Модули и реальные функции

### Обучение (`academy`, `attendance_matrix`, `academic_progress`, `testing`, `training`, `reports`)
* Группы, студенты, курсы и учебные планы, кабинеты; генератор занятий из
  расписания группы (`services/lesson_generator.py`), аудит конфликтов
  расписания.
* Расписание академии по кабинетам (день/неделя), свободные кабинеты.
* Занятие: старт/завершение, посещаемость, домашние задания, оценки.
* Матрица посещаемости групп, сводки, мониторинг, экзамены и тесты.
* Ежемесячные отчёты тренеров, отчёты для родителей (PNG/PDF через Playwright).
* Стипендии (`scholarships`), лидерборд, проекты студентов.

### Аналитика и KPI (`performance`, `analytics`, `kpi`)
* Аналитика за период: тренеры, группы, студенты, посещаемость, выполнение ДЗ,
  средний балл, проведённые занятия; KPI каждого тренера.
* Экспорт в PDF и Excel.
* Ежедневные снимки статистики (Celery: `performance.capture_daily_snapshots`).

### HR и учёт рабочего времени (`staff_attendance`, `recruitment`, `operations`, `worklog`)
* Постоянный QR-код офиса (ссылка + код офиса, без секретов).
* Отметка прихода/ухода: свежая геолокация браузера → сервер проверяет
  геозону (радиус), точность GPS, при необходимости — сеть офиса;
  идемпотентность повторов; расчёт опоздания по графику сотрудника.
* Отчёты: приход, уход, продолжительность, опоздания, «нет ухода»; экспорт CSV;
  ручные исправления с журналом.
* Незакрытые смены закрываются автоматически (Celery, каждый час).
* HR-кабинет: вакансии, кандидаты, интервью, воронка найма.
* Операционный дашборд: отделы, задачи, ежедневный контроль, проблемы.

### Финансы и зарплата (`billing`, `accounting`)
* Договоры студентов, тарифы с версиями цен, скидки, брони, предоплаты.
* Начисления из проведённых уроков (Celery каждые 30 мин), учебные месяцы,
  распределение платежей, чеки, возвраты, звонки родителям.
* Статусы «к оплате / скоро / просрочено» вычисляются из уроков и денег.
* Зарплата: правила по типу (процент от стоимости курса, фиксированный оклад,
  ставка), периоды 1–15 / 16–конец месяца, утверждение, план выплат,
  «Моя зарплата» для сотрудника, аналитика зарплат, журнал изменений.

### Прочее
* Новости академии и CMS публичного сайта, маркетинг, push-уведомления,
  импорт/экспорт данных (`data_io`).

## Какие процессы действительно автоматизированы

| Процесс | Как |
|---|---|
| Учёт оплаты | Celery: `billing.process_completed_lessons` (30 мин), `billing.run_daily` (6 ч), `billing.notify_accountants` (10 мин) — начисления, просрочки, уведомления |
| Учёт рабочего времени | QR + геозона, расчёт опозданий; `staff_attendance.close_stale_sessions` (каждый час) |
| Аналитика | Метрики считаются из занятий, посещаемости и ДЗ; ежедневные снимки `performance.capture_daily_snapshots` |
| Операционный контроль | `operations.run_periodic` — повторяющиеся задачи, напоминания, поиск проблем |
| Зарплата | Расчёт процента за период по правилам, план выплат, сверка (`payroll_autorun`, `payroll_reconcile`) |
| Расписание | Генерация занятий из расписания групп и учебного плана |

## Что показано в ролике и на каком стенде

Стенд: локальная PostgreSQL, `runserver` под `faketime` (12.11.2026, 10:20 по
Бишкеку), Vite dev-server. Данные — штатные seed-команды + `prepare_stand.py`.
QR-отметка прихода выполнена по-настоящему: Playwright эмулировал iPhone 13 с
геолокацией в 11 м от центра офиса, страница `/attendance/scan?office=…`
прошла весь поток (проверка офиса → геолокация → запрос на сервер), сервер
создал сессию прихода.

Не показано (есть в системе, но не вошло по хронометражу): тренинг-портал,
публичный сайт и CMS, рекрутинг подробно, стипендии, экзамены.
